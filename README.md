# CodeForge Strategy OS

CRM-like рабочее пространство для проверки бизнес-гипотез до запуска. Система объединяет pipeline потенциальных клиентов, доказательства по компаниям, расчет unit-экономики, сценарии capacity и Decision Center с логикой Go / No-Go.

## Что реализовано

- **Overview / Control Room** — общий сигнал по доказательствам, CRM и экономике.
- **Companies** — компании, сегмент, город, стадия, приоритет, заметки и активности.
- **Verification** — источники каждого наблюдения, даты, confidence и статусы `unverified`, `in_review`, `verified`, `conflict`, `rejected`, `stale`.
- **Scenarios** — conservative / base / optimistic из единого файла входов.
- **Decision Center** — прозрачные пороги LTV/CAC, payback, delivery load и минимальное число подтвержденных фактов.
- **Документация** — шесть отдельных рабочих страниц: Product Knowledge Base с capability map и каталогом фаз, Sales Playbook с исследовательскими сигналами и персонализированными обращениями, а также AI OS, Operating Model, Upsell Matrix и White Label Playbook с operational checklists.
- **История запусков** — результаты последних расчетов сохраняются в состоянии workspace.

## Единый источник расчетов

`primitives.json` — канонический и версионируемый набор входов. В нем находятся ставки, fixed costs, capacity, продукты, три сценария, benchmark-гипотезы, пороги решения и текстовые правила формул.

Числа из расчетов не дублируются в UI или документации. CRM-данные и доказательства хранятся отдельно от primitives и по умолчанию не смешиваются с неподтвержденными рыночными гипотезами.

## Запуск

Требуется Node.js 18+ и Bun.

```bash
bun install
bun run dev
```

Откройте Vite preview и используйте навигацию приложения. Дев-сервер слушает `0.0.0.0`.

Проверки:

```bash
bun run typecheck
bun test tests/calculations.test.js
```

## Исследовательский dataset

При первом запуске пустого local workspace система загружает воспроизводимый open-web seed из `src/data/researchSeed.ts`: 32 компании, 61 evidence и 18 ручных задач с публичными URL. В white-label-контуре 10 записей — micro/solo discovery-кандидаты, а 3 старые записи сохранены только как `legacy_context` для аудита и не входят в target shortlist. Существующее local workspace мигрируется по версии seed: недостающие research-компании, evidence и задачи добавляются без перезаписи пользовательских записей. Канонический research dataset в `primitives.json` содержит 57 источников, 19 ценовых наблюдений, 14 срезов 2ГИС (9 self-storage/OOH и 5 white-label), 4 социальных сигнала и 4 производные оценки; текущий pass описан в `RESEARCH_DATASET_2026-08-15.md`.

Seed не маскирует гипотезы под факты: компании имеют статус `in_review`, наблюдения несут `verified` / `partial` / `stale`, производные оценки помечены как публичная выборка, а OOH-оценки 109,1 и 114,6 млрд ₽ сохранены как конфликт опубликованных методик. Срезы 2ГИС и VK являются shortlist-сигналами и не доказывают размер рынка. Если workspace уже содержит пользовательские данные, seed их не заменяет и не удаляет: миграция только дополняет отсутствующие записи по стабильным ID.

## Хранение и настройки

Без credentials приложение работает в `local-demo` режиме: состояние CRM сохраняется в `localStorage` браузера. В проекте есть безопасный адаптер Supabase и SQL-схема в `supabase/schema.sql`; для cloud persistence нужно задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` через настройки окружения, не записывая секреты в репозиторий.

## White-label research и API

Фокус текущего исследования — white-label партнеры в Екатеринбурге, Тюмени, Перми, Челябинске и Сургуте. В `primitives.json.white_label_research` сохранены пять снимков публичной выдачи 2ГИС, социальный сигнал VK, ограничения методики и connector manifest. Снимок первой страницы — shortlist, а не census; филиалы и рейтинги не превращаются в долю рынка.

В UI на странице **Сценарии** есть безопасный импорт ответа официального API: нормализаторы `src/lib/researchImport.ts` принимают `result.items` 2ГИС или `response.items` VK, сохраняют только публичные поля и помечают импорт `partial`. Ключи не вводятся в браузер и не попадают в `primitives.json`; live-вызов должен выполняться серверным адаптером после добавления `TWOGIS_API_KEY` и `VK_USER_ACCESS_TOKEN` через API Keys. Telegram оставлен manual-only, потому что Bot API не дает общего поиска произвольных каналов.

Публичные страницы, 2ГИС и социальные сигналы не заменяют интервью и оплаченный пилот. Платежи и авторизация не включены: система сначала должна подтвердить рынок и экономику через реальные источники и пилоты.

## Принцип принятия решения

`unverified` не считается доказательством. Сценарий получает флаги, если LTV/CAC, payback, break-even или delivery capacity не проходят пороги из `primitives.json`. Вердикт остаётся условным или `NO-GO`, пока не собран минимальный объем проверяемых данных.
